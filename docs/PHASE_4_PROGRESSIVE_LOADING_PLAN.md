# Phase 4 progressive loading amendment — approved October 4, 2026

The user selected Option 1 and authorized progressive loading after reviewing the failed P4.9 cold measurements. P4.1–P4.8 acceptance and the original P4.9 evidence remain intact. This amendment includes the seven startup/date-jump requirements and the subsequent approved accuracy clarification. It does not add Phase 4B or Phase 5 content.

## Science basis and representation

Planets continue to use astronomy-engine 2.1.19 locally. The original five-epoch failures are reproduced in `docs/science/analytic-ephemeris-audit.json`: ten of eleven bodies fail the combined 30 arcsecond / 1e-5 relative-radius requirement, predominantly radius. Planetary angular maxima are 2–19 arcseconds at those dates. Independent explicit TT conversion and direct library calls agree with the application's uncorrected adapter within 0.000027 km. The queries request geometric SSB, ICRF frame-plane vectors in KM-S and TDB. No UTC/TT, ecliptic/equatorial, or heliocentric/barycentric mix-up was found. The Sun's small barycentric displacement is approximated by the library using the four giant planets; its barycentric angular errors are a separate issue from its apparent direction seen from Earth. The audit also reports all 24 holdouts per body. It is a finite validation, not a continuous accuracy proof.

The application will preserve the accepted residual model using **fitted cubic polynomial coefficients**, not downloadable raw planetary position samples. Each polynomial is the exact cubic Hermite fit to the already accepted endpoint residuals and derivatives. Evaluating the polynomial and its derivative preserves that model to floating point roundoff, avoiding an additional approximation tolerance or fitting to test epochs. Fixed 28 Julian-day TDB chunks contain the needed coefficient intervals with overlapping guard intervals. A body's correction is hundreds of bytes; all current-date corrections together must fit within 8 KB. The six accepted orbital models retain the actual osculating elements and the global sample grid, with neighbors on both sides of chunk boundaries. Today's combined bundle is subject to a measured 16 KB cap. If either cap fails, the build fails; do not silently enlarge it.

Generation uses only the checked-in source bins. It never regenerates Horizons references, downloads fresh science data, changes thresholds or extrapolates a correction. Content generation hashes include the source files and encoder implementation. URLs have a version hash and a fixed time index, allowing `public, max-age=31536000, immutable`. A small generated manifest describes coverage and the version, without a large list of per-file URLs in the JavaScript bundle. The original full bins remain available for independent comparisons, never requested by the new app startup.

## File-level implementation sequence

1. **Audit and exact chunk foundation:** `tools/audit-analytic-ephemeris.ts`, `tools/fixtures/build-runtime-chunks.ts`, shared binary/coefficients code in `packages/astro/src/ephemeris`, and chunk-boundary tests. Compare every neighboring pair and independent original Horizons/holdout references, position and velocity; malformed/missing buffers must never write a failed state.
2. **Progressive texture foundation:** `packages/engine/src/assets/AssetManager.ts` and `TexturePlaceholder.ts`. Draw with neutral download-free texels immediately, stream real 1K maps after the first scene submission, then upgrade desktop detail. Mobile is capped at 1K. Keep texture identities, data-map conventions and GPU disposal correct on both backends. Delayed or failed KTX requests must not prevent a first frame. Test disposal during a request, failed upgrades, quality changes and mobile caps. The real 1K baseline follows the neutral first-frame placeholder; allocating twenty-nine 1K RGBA placeholder maps would waste memory and delay the frame.
3. **Per-object data and cache:** an engine-owned chunk loader with deduplication, bounded cache/concurrency, cancellation, retry and forward/reverse rate-aware prefetch. Generic streamed astro providers expose current-epoch coverage. Analytics work without network: missing corrections use freshly calculated states marked **approximate**, including offline and dates beyond correction coverage within the supported timeline. The six non-analytic objects are hidden/marked loading until their requested epoch is covered; never reuse previous-date coordinates. Late responses cache safely but cannot restore an older request or camera intent.
4. **Scene/date integration:** `SpaceEngine.ts`, `EntityRegistry.ts`, `FrameTree.ts`, camera commands and object snapshots/cards. Keep rendering through jumps; invalidate frame caches when data arrives at a paused epoch. Guard metrics, child transforms, labels, point layers, orbit curves and camera targets against unavailable positions. Remove whole-scene time-jump fading. Defer full orbit curves until after the first frame; fetch their necessary ranges at lower priority. Keep current objects and playback prefetch ahead of curve work. Preserve route/history/camera ownership and truthful loading/approximate labels.
5. **Build and cache gates:** generated version/coverage metadata, `apps/web/next.config.ts` and startup-budget tooling. Enforce data caps and a **1,500,000-byte total startup download cap**, including HTML, CSS, initial route/shell/engine JavaScript, critical data, star/shape bytes and any requests contributing before the first actual frame. Audit emitted/requested bundles and keep the existing 200,000-byte shell, 450,000-byte engine and 80,000,000-byte texture gates. Missing metadata or incomplete accounting fails the check. Verify immutable headers against production HTTP responses and repeated chunk requests against actual network records.
6. **Measured acceptance:** extend `e2e/phase-four-performance.spec.ts` and dedicated progressive-loading coverage. Use cache-disabled fresh contexts and the original protocols: desktop 100 Mbps/20 Mbps/20 ms/CPU1; simulated 4G 4 Mbps/1 Mbps/150 ms/CPU4. Every measured first actual rendered frame must be **≤2.5 seconds desktop / ≤5 seconds simulated 4G**. Enforce startup bytes in the same tests. Desktop date jumps must reach the requested epoch with all required positions valid in **≤1 second** while rendering continues. Include multiple distant jumps, cancellation/races, offline correction fallback, late/failed per-object data, both playback directions at one year/second, boundary crossings, and delayed 1K/detail textures. Approximate fallback is not counted as a corrected-accuracy pass. Re-run independent science, both physical GPU backends, geometry/texture stability, consumer regression/accessibility/profile gates and the required same-runner reference/candidate CPU comparison.
